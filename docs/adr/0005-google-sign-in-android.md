# ADR 0005. Вход в Google на Android

Статус: принято по документации, проверяется в фазе 0 после настройки проекта Google Cloud.

## Контекст

Google блокирует вход внутри встроенных WebView. На Android нужен вход аккаунтом, уже добавленным в телефон. Своего сервера нет.

## Варианты

1. `AuthorizationClient` из Google Play services (`play-services-auth`).
2. Устаревший Google Sign-In для Android (раздел Legacy в документации).
3. Системный браузер (Custom Tabs) с клиентом «Desktop app» и loopback-адресом.

## Решение

Вариант 1, через собственный мобильный плагин Tauri на Kotlin.

- В Google Cloud создаётся клиент типа «Android» (имя пакета и SHA-1) в том же проекте, что и клиент Windows. Отдельные клиенты для отладочной и релизной подписи.
- `Identity.getAuthorizationClient(activity).authorize(...)` с правами `drive.file` и `drive.appdata`. Если нужно согласие, запускается `PendingIntent` из ответа.
- Ответ — токен доступа примерно на час. Повторный вызов выдаёт новый без участия пользователя. Токена обновления нет, хранить нечего.
- Вариант 3 противоречит назначению типа клиента и не даёт выбора аккаунта телефона. Вариант 2 устарел.

## Последствия

- Нужны Google Play services: эмулятор с образом Google Play. На телефонах без них Google Drive недоступен, интерфейс предлагает Dropbox.
- Реализация плагина — фаза 2. В фазе 0 проверяется только сам вход, когда владелец создаст клиенты.
