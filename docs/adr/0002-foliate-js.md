# ADR 0002. Подключение foliate-js

Статус: принято.

## Контекст

У foliate-js нет релизов, API нестабилен. Автор советует подключать библиотеку как git submodule. Пакет `foliate-js` в npm опубликовал не автор. Readest подключает свой форк `readest/foliate-js` тоже через submodule.

## Варианты

1. git submodule основного репозитория `johnfactotum/foliate-js` с зафиксированным коммитом.
2. git submodule форка Readest.
3. Пакет из npm.
4. Копия исходников в репозитории.

## Решение

Вариант 1. Submodule лежит в `vendor/foliate-js`, коммит зафиксирован в git. Обновление — отдельным коммитом с прогоном тестов локаторов (CFI для FB2 и других не-EPUB форматов зависит от версии движка, см. SPEC, раздел 4).

- Свой загрузчик книг (`src/reader/book-loader.ts`) вместо `makeBook` из `view.js`. Он определяет формат по сигнатуре и имени без учёта регистра, приводит имена картинок в CBZ к нижнему регистру и не тянет PDF через foliate-js.
- PDF открывает наш просмотрщик на `pdfjs-dist`. Копия PDF.js внутри foliate-js (`vendor/pdfjs`) не используется. Vite всё равно кладёт её в сборку отдельным чанком, потому что `view.js` ссылается на неё динамическим импортом. Это лишний размер, но не вторая копия в работе. Убрать при оптимизации размера.
- Скрипты из книг запрещены политикой CSP в `tauri.conf.json`. Документы разделов создаются как `blob:` и наследуют CSP приложения.

## Последствия

- После `git clone` нужен `git submodule update --init` (в README).
- Версия движка записывается в локатор (`engine`).
