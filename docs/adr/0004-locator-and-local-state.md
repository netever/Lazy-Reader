# ADR 0004. Локатор позиции и локальное состояние в фазе 0

Статус: принято для прототипа, уточняется в фазах 1 и 3.

## Контекст

Позиция должна переживать смену шрифта, экрана и устройства (SPEC, раздел 4). Синхронизации в фазе 0 нет, но формат состояния должен совпадать с будущими облачными файлами.

## Решение

- Состояние книги хранится локально в каталоге данных приложения: `state/<book-id>/<device-id>.json`, в формате SPEC. Запись атомарная: временный файл, затем переименование. Неизвестные поля сохраняются.
- Локатор EPUB, FB2 и других форматов foliate-js: `cfi`, `section`, `quote` (около 32 символов до и после начала страницы), `engine` (коммит foliate-js), `totalProgression`.
- Локатор PDF: `pdf.page` и `totalProgression = (page - 1) / pages`.
- Восстановление: сначала `cfi`. Если цитата на месте не совпадает, ищем `quote.exact` в разделе `section`. Если и это не удалось, идём по `totalProgression`.
- **Временное упрощение.** В фазе 0 `totalProgression` для foliate-js берётся из `fraction` движка. Это приближение: оно зависит от размера разделов в байтах и разбиения на страницы. В фазе 3 заменить на счёт по символам текста (SPEC, раздел 4).
- `device-id` — UUID, создаётся при первом запуске в `device.json`.

## Последствия

- В прототипе позиции между устройствами не сравниваются, поэтому приближённый `totalProgression` не мешает.
