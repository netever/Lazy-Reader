# ТЗ для Claude Code: кроссплатформенная читалка

Oct 26, 2026 · @Vladimir

## Задача и как пользоваться документом

Построй кроссплатформенную читалку книг для одного владельца: сначала Windows и Android, позже iOS и macOS, с синхронизацией через его Google Drive или Dropbox и без собственного сервера.

**Продукт.** Читалка EPUB, PDF и FB2 (позже MOBI, AZW3, CBZ и другие форматы без DRM). Синхронизирует позицию чтения, заметки и закладки между устройствами через облако читателя. В фоне собирает файлы с заметками, которые открываются в других программах. Листает страницы с анимацией, читает текст вслух системным голосом.

**Владелец.** Приложение для себя, но возможна коммерциализация, если оно понравится многим. Поэтому лицензии зависимостей должны допускать коммерческое использование. Владелец сильнее всего в Python, а TypeScript и Rust знает хуже. Объясняй нетривиальные решения в README и в записях решений (ADR), а код держи простым.

**Как пользоваться этим документом.**

1. Читай разделы по порядку. Раздел 2 — решения владельца, их не пересматривай и не переспрашивай.
2. Работай по фазам из раздела 9. Не начинай следующую фазу, пока владелец не подтвердил текущую.
3. Пометка «проверить» значит, что факт не подтверждён. Проверь по официальной документации и запиши результат в `docs/CHECKS.md`.
4. Факты о сторонних сервисах (Google, Dropbox, Tauri, библиотеки) собраны из поиска в октябре 2026 и могли устареть. Официальная документация главнее этого документа.
5. Язык интерфейса — русский, но тексты вынеси в файлы локализации, чтобы добавить английский позже. Документацию проекта пиши по-русски, идентификаторы и комментарии в коде по-английски.

## Стек, репозиторий и зависимости

Приложение состоит из ядра на Rust и веб-интерфейса на TypeScript внутри Tauri 2. Книги рисуют готовые движки в WebView, а Rust отвечает за файлы, токены и фоновую работу.

| Слой | Технология | Роль |
| --- | --- | --- |
| Оболочка | Tauri 2 | Окно приложения для Windows и Android, позже iOS и macOS |
| Интерфейс | TypeScript, React, Vite | Библиотека, читалка, настройки. Заменить только записью в ADR |
| EPUB, MOBI, AZW3, FB2, CBZ | foliate-js (MIT) | Разбор и показ. Подключай как git submodule [johnfactotum/foliate-js](https://github.com/johnfactotum/foliate-js) с зафиксированным коммитом: релизов нет, API нестабилен, так советует автор. Пакет `foliate-js` в npm опубликовал не автор, его не бери. Readest подключает так же свой форк readest/foliate-js (MIT), переход на форк только через ADR. Обязательно задай CSP, запрещающую скрипты из книг: foliate-js их не блокирует |
| PDF | PDF.js (Apache-2.0) | Показ страниц. В foliate-js лежит своя копия PDF.js (`vendor/pdfjs`), в сборке держи одну версию |
| Локальная база | SQLite | Кэш: библиотека, оглавление, обложки, расчёт страниц. Источник истины для синхронизации — файлы в облаке, а не база |
| Ядро | Rust | Файлы, SHA-256, работа с облаками, токены, фоновые задачи |
| Токены | Системное защищённое хранилище (Windows Credential Manager, Android Keystore) | Токены не лежат в открытом виде. Исключение: токены Google на Android хранит Google Play services, приложение их не сохраняет (раздел 5). Конкретную библиотеку выбрать, записать в ADR и проверить на обеих платформах |
| Озвучка | Windows: Web Speech API в WebView2. Android: нативный плагин на системном `TextToSpeech` | В Android WebView `window.speechSynthesis` нет, поэтому там нужен плагин. Проверить, что системные голоса доступны на Windows и Android |
| Шрифты | Только свободные (OFL) | Лицензию каждого шрифта записать в `docs/LICENSES.md` |

### Правила для зависимостей

1. Перед добавлением зависимости проверь лицензию и допиши строку в `docs/LICENSES.md`. Подходят только лицензии из раздела 2.
2. Зависимостей должно быть как можно меньше. Не тащи библиотеку ради десяти строк кода.
3. Открытые читалки (KOReader, Readest, Foliate, Thorium) можно изучать ради идей. Их код и ресурсы не копируй: Readest и KOReader под AGPL-3.0, приложение Foliate под GPL-3.0 (проверено по GitHub в октябре 2026). Исключение — сам foliate-js, он под MIT.
4. Тестовые книги бери только свободные (общественное достояние). Книги владельца и книги с DRM в репозиторий не попадают.
5. Лицензии проверяй автоматически: `cargo deny check licenses` для Rust и проверка лицензий npm-зависимостей, обе в CI. В дереве зависимостей Tauri уже есть Zlib, Unicode-3.0 и MPL-2.0, это ожидаемо.
6. MIT, BSD и Apache-2.0 требуют прикладывать тексты лицензий, а Apache-2.0 ещё и NOTICE. Собирай их автоматически и показывай в приложении на экране «О программе → Лицензии».
7. Среда разработки: macOS, там запускается Claude Code. Целевые платформы Windows и Android. Для Android нужны Android Studio, SDK, NDK и цели сборки Rust. Точные шаги возьми из документации Tauri 2 и запиши в README.

## Данные в облаке и слияние

Всё, что синхронизируется, лежит в папке приложения в облаке читателя как небольшие JSON-файлы. Каждое устройство пишет только свои файлы, поэтому записи не конфликтуют, а данные сливаются при чтении. Локальная SQLite — это кэш, его можно пересобрать из облака.

### Структура папки

```text
Читалка/                              папка приложения в облаке
  Книги/<Автор - Название>.<ext>      книги под обычными названиями
  meta/<book-id>.json                 описание книги и её идентификаторы
  state/<book-id>/<device-id>.json    позиция, заметки и закладки одного устройства
  library/<device-id>.json            полки и теги одного устройства
  devices/<device-id>.json            имя устройства, версия приложения
  Заметки/<Название>.md               производный файл, раздел 6
  С заметками/<Название>.pdf          производный файл, раздел 6
```

- `device-id` — UUID, создаётся при первом запуске и хранится локально.
- `book-id` — UUID, создаётся при первом импорте. `sha256` — хэш байтов исходного файла.
- Если одну книгу импортировали на двух устройствах до синхронизации, получатся два `book-id`. При слиянии meta-файлов с одинаковым `sha256` главным считается меньший `book-id`, второй записывается в `aliases`, а их state-файлы объединяются.
- Имя файла книги: «Автор - Название.ext». Убери символы, запрещённые в Windows (`\ / : * ? " < > |`), ограничь длину и при совпадении добавь « (2)». Имя файла не идентификатор. Книгу определяет `meta`: ищи файл по `fileName`, а если его нет, по `sha256` среди файлов папки.
- Google Drive с правом `drive.file` видит только файлы, созданные приложением или выбранные в Google Picker. Книги, которые владелец сам положил в `Книги/` через сайт Drive или другую программу, приложение не увидит. Папку «Читалка», созданную вручную, тоже не увидит и создаст свою. Поэтому книги попадают в облако только через импорт в приложении. Расширение файла в имени пиши строчными буквами.
- В Dropbox с типом «App folder» корень — `Apps/<имя приложения>/`, и приложение видит в нём всё, в том числе файлы, положенные вручную.

### meta/\<book-id>.json

```json
{
  "schema": 1,
  "bookId": "uuid",
  "aliases": [],
  "sha256": "hex",
  "previousSha256": [],
  "fileName": "Автор - Название.epub",
  "format": "epub",
  "title": "Название",
  "authors": ["Автор"],
  "language": "ru",
  "addedAt": 1761440000000,
  "updatedAt": 1761440000000
}
```

### state/\<book-id>/\<device-id>.json

```json
{
  "schema": 1,
  "deviceId": "uuid",
  "bookId": "uuid",
  "position": { "locator": {}, "updatedAt": 1761440000000 },
  "annotations": [],
  "readingSessions": []
}
```

Локатор описывает место в книге несколькими способами сразу, потому что страницы зависят от шрифта и экрана:

```json
{
  "format": "epub",
  "engine": "foliate-js@<commit>",
  "cfi": "epubcfi(/6/4!/4/2/1:0)",
  "section": 3,
  "progression": 0.42,
  "totalProgression": 0.18,
  "quote": { "prefix": "…", "exact": "…", "suffix": "…" },
  "pdf": { "page": 12, "x": 0.1, "y": 0.3 }
}
```

`progression` — доля внутри главы, `totalProgression` — доля книги по объёму текста в символах, а не по страницам, поэтому она одинакова на всех устройствах. Считай её сам по числу символов текста до места. Поле `fraction` из события `relocate` foliate-js для этого не годится: оно взвешивает разделы по размеру в байтах, а внутри раздела считает по страницам, то есть зависит от шрифта и экрана.

Для PDF заполняется `pdf`, для остальных форматов `cfi`. Проверено по коду foliate-js (октябрь 2026):

- `view.getCFI()` выдаёт CFI для всех форматов. У EPUB это настоящий CFI. У FB2, MOBI, AZW3 и CBZ первая часть условная, `/6/<2 × (номер раздела + 1)>`, а путь внутри раздела считается по HTML, который foliate-js собирает из книги.
- Поэтому CFI для FB2 понимает только наше приложение с той же версией foliate-js. После обновления foliate-js прогоняй тесты локаторов. Если CFI не находится или текст на месте не совпадает с `quote`, восстанавливай место по `quote`, затем по `section` и `progression`. Версию движка (коммит foliate-js) храни в локаторе в поле `engine`.
- FB2 делится на разделы по секциям верхнего уровня первого `<body>`. Кодировку (например, windows-1251) foliate-js берёт из XML-заголовка.
- У CBZ каждый раздел — одна картинка, картинки отсортированы по имени. CFI фактически означает номер страницы, текста и `quote` нет. Для CBZ доступны только закладки, выделения и заметки к тексту не делай.
- foliate-js узнаёт FB2, `.fb2.zip`, `.fbz` и CBZ только по имени файла или MIME-типу, причём с учётом регистра. Передавай в движок `File` с исходным именем и расширением строчными буквами. Картинки в CBZ он ищет тоже только по строчным расширениям (`.jpg`, но не `.JPG`), поэтому для CBZ сделай свой загрузчик архива с приведением имён.

Запись заметки:

```json
{
  "id": "uuid",
  "type": "highlight",
  "color": "yellow",
  "target": {
    "epub": { "startCfi": "…", "endCfi": "…" },
    "pdf": { "page": 12, "rects": [[0.1, 0.3, 0.5, 0.02]] },
    "quote": { "prefix": "…", "exact": "…", "suffix": "…" }
  },
  "text": "выделенный текст",
  "note": "текст заметки",
  "createdAt": 1761440000000,
  "updatedAt": 1761440000000,
  "deleted": false
}
```

`type` — `highlight`, `note` или `bookmark`. Для PDF `rects` задаются в долях страницы от 0 до 1, при записи в PDF переводятся в `QuadPoints`.

`readingSessions` хранит интервалы чтения для статистики: `id`, `start`, `end` в миллисекундах. Записи сливаются по тем же правилам, что и заметки.

### Правила слияния

1. Прочитай state-файлы всех устройств для книги и объедини записи.
2. Для записей с одним `id` побеждает больший `updatedAt`, при равенстве большее значение `deviceId` по строковому сравнению.
3. Удаление — это запись с `deleted: true` и новым `updatedAt` (надгробие). В фазах 0–3 надгробия не чисти.
4. Позиция: побеждает больший `updatedAt`. Защита от прыжка: если позиция другого устройства отличается от локальной по `totalProgression` больше порога, не прыгай молча, а спроси «Перейти на позицию другого устройства?». Порог вынеси в настройки, значение по умолчанию выбери и запиши в ADR.
5. `updatedAt` одного устройства должен строго возрастать: `max(now, last + 1)`. Расхождение часов между устройствами считается известным ограничением, запиши его в ADR. Если появятся проблемы, рассмотри гибридные логические часы.
6. Пиши только свои файлы. Перед записью сверь версию файла в облаке (у Drive `version` или `headRevisionId`, у Dropbox `rev`), чтобы не затереть чужую правку.
7. При перезаписи сохраняй неизвестные поля. Файл с большим `schema`, чем знает приложение, не затирай, а покажи предупреждение.
8. `library/<device-id>.json` сливается так же: записи полок и тегов с `id`, `updatedAt` и `deleted`.

## Синхронизация и вход в облака

Синхронизацию строй на общем интерфейсе провайдера, чтобы Google Drive, Dropbox, папка на диске и тестовая память были взаимозаменяемы. Слияние данных (раздел 4) не должно знать, какой провайдер под ним.

```text
SyncProvider
  authorize()                              вход, сохранение токенов
  list(path)                               файлы и их версии (version или rev)
  read(path)                               содержимое и версия
  write(path, data, expectedVersion)       запись с проверкой версии
  delete(path)
  changes(cursor)                          изменения после курсора, если провайдер умеет
```

Реализации: `GoogleDriveProvider`, `DropboxProvider`, `MemoryProvider` для тестов и `LocalFolderProvider`. В фазе 2 `LocalFolderProvider` нужен для тестов, позже он станет провайдером для читателя.

### Когда синхронизировать

1. При открытии книги сразу покажи текст по локальным данным. Чужие данные подтяни в фоне. Если позиция другого устройства дальше порога, задай вопрос из раздела 4.
2. При закрытии книги и уходе приложения в фон запиши свой state-файл.
3. Пока книга открыта, запись по таймеру и через небольшую задержку после новой заметки. Интервал вынеси в настройки.
4. Все изменения сначала кладутся в локальную очередь. При отсутствии сети очередь копится, потом уходит с нарастающей паузой между повторами. Офлайн приложение полностью работает.

### Google Drive

- Права: `drive.file` и при необходимости `drive.appdata`. Оба нечувствительные: проверка приложения не нужна, лимита в 100 пользователей и экрана «приложение не проверено» нет. Права `drive` и `drive.readonly` не запрашивай: они ограниченные и требуют проверки безопасности каждый год.
- Приложение создаёт видимую папку «Читалка» и работает только в ней. Что `drive.file` не видит, описано в разделе 4.
- **Проверка № 1.** По документации Google доступ `drive.file` принадлежит проекту Google Cloud, а не отдельному OAuth-клиенту: в Picker идентификатор приложения — это номер проекта. Значит, клиенты Windows и Android одного проекта видят файлы друг друга. Все клиенты создавай в одном проекте. В фазе 0 подтверди тестом: файл, созданный на Windows, читается и меняется на Android, и наоборот. Если не подтвердится, остановись и сообщи владельцу: он решит, например, начать с Dropbox.
- Вход на Windows: клиент типа «Desktop app», системный браузер, возврат на loopback-адрес `http://127.0.0.1:<порт>`, PKCE. Google выдаёт для этого клиента `client_secret` и ждёт его при обмене кода на токен. Для установленных приложений Google сам не считает его секретом, он окажется в сборке.
- Вход на Android: клиент типа «Android» с именем пакета и отпечатком SHA-1 подписи. У отладочной и релизной подписи отпечатки разные, на каждый нужен свой клиент; при Google Play App Signing берётся отпечаток из Play Console. В коде этот идентификатор не указывается. Вход идёт через `Identity.getAuthorizationClient(activity).authorize(...)` из `play-services-auth` с правами `drive.file` и `drive.appdata`. Система показывает выбор из аккаунтов, уже добавленных в телефон, и экран согласия. Ответ — токен доступа примерно на час, повторный вызов `authorize()` выдаёт новый без участия пользователя. Токена обновления нет, хранить его не нужно. Credential Manager и устаревший Google Sign-In для доступа к Drive не нужны.
- Для Tauri вход на Android — свой мобильный плагин на Kotlin. Вход в Google внутри WebView Google блокирует, поэтому через WebView его не делай. Нужны Google Play services: эмулятор бери с образом Google Play. На телефоне без Google Play services покажи понятное сообщение и предложи Dropbox. Решение запиши в ADR.
- Выбор книг, уже лежащих в Drive, делается через Google Picker, только по просьбе владельца. На Windows Picker открывается в системном браузере (параметры `prompt=consent` и `trigger_onepick=true`), на Android — через тот же `AuthorizationClient` с параметром `PICKER_OAUTH_TRIGGER`. Запрос Picker содержит только `drive.file` и не совмещается с другими правами.
- Статус приложения в Google Cloud должен быть «In production». В статусе «Testing» войти могут только тестовые пользователи из списка, а токены обновления живут 7 дней. Проверка бренда (название и логотип на экране согласия) для владельца не нужна.
- Идентификаторы клиентов и `client_secret` настольного клиента держи в локальной конфигурации, которую не коммитят.
- Версия файла: в Drive API v3 нет поля `etag` (оно было в v2). Используй `version` или `headRevisionId` и запиши выбор в ADR. Атомарной записи с проверкой версии в Drive нет, поэтому сверяй версию прямо перед записью. Гонка безопасна, потому что каждое устройство пишет только свои файлы.

### Dropbox

- Тип доступа «App folder». Вход по PKCE с `token_access_type=offline`. Токен обновляется без секрета приложения: нужны только `client_id` и `refresh_token`. Refresh-токен храни в защищённом хранилище, на Android в том числе.
- Страницу входа открывай в системном браузере, на Android — в Custom Tabs. Тогда работает и кнопка входа через Google на странице Dropbox: она доступна, если почта аккаунта Dropbox совпадает с Google. Приложение при этом всё равно получает токен Dropbox. Внутри WebView вход через Google заблокирован. Командные (team) права не запрашивай: с ними вход через Google зацикливается.
- Redirect URI регистрируй в консоли Dropbox точно. На Windows — `http://localhost:<фиксированный порт>`: поддержку случайного порта Dropbox не подтверждает. На Android — своя схема или App Link через deep link Tauri. Запасной вариант без redirect: Dropbox показывает код, владелец вставляет его в приложение.
- Изменения отслеживай курсором (`list_folder` и `list_folder/continue`). Всегда обрабатывай `has_more`. Пути строй относительно корня папки приложения.
- Версия файла — поле `rev`. Пиши с проверкой `rev` (режим `update`).
- Приложение в режиме разработки подключают до 500 пользователей, а после 50-го есть две недели на получение статуса production. Владельцу production не нужен.

### Безопасность

- Токены только в системном защищённом хранилище. В логи не пиши токены и содержимое книг, только идентификаторы и коды ошибок.
- Выход из аккаунта удаляет токены.
- Приложение никогда не удаляет книги владельца в облаке без явного подтверждения.

### Тесты

- Автоматические тесты слияния на `MemoryProvider`: два–три «устройства», правки офлайн, конфликты, надгробия, неизвестные поля.
- Ручной чек-лист на Windows и Android: позиция, новая заметка, удаление заметки, работа офлайн и возвращение сети.

## Заметки и фоновая сборка файлов

Главный источник данных — state-файлы из раздела 4. Чтобы заметки можно было открыть в других программах, приложение само пересобирает производные файлы и не трогает оригинальную книгу. Исключение — опция записи в оригинал PDF.

| Формат книги | Производный файл | Где лежит | Как его видят другие программы |
| --- | --- | --- | --- |
| PDF | Копия с аннотациями | `С заметками/<Название>.pdf` | Обычный PDF с выделениями и заметками |
| EPUB, FB2 и остальные | Файл заметок в Markdown | `Заметки/<Название>.md` | Текстовый файл, открывается в Obsidian и любом редакторе |

Позицию чтения в файлы не выводим: общего стандарта для неё нет.

### Когда собирать

1. При закрытии книги, после синхронизации, принёсшей чужие заметки, и по команде «Пересобрать».
2. В фоне и с низким приоритетом, интерфейс не блокируется. Если приложение закрыли раньше, сборка идёт при следующем запуске.
3. Результат зависит только от слитого состояния заметок и оригинала, имена файлов детерминированы. Тогда пересборка на двух устройствах даёт одинаковый результат и конфликт записи безвреден.
4. Не пересобирай, если слитое состояние не изменилось. Хэш состояния храни в локальной базе.
5. Запись атомарная: сначала временный файл, затем замена.

### PDF

- Копия делается из оригинала. Для первой версии достаточно двух типов стандартных аннотаций: выделение (`Highlight` с `QuadPoints` и цветом) и заметка (`Text`). Дописывай их в конец файла (инкрементальное обновление), не пересобирай страницы оригинала.
- Библиотеку для записи выбери в фазе 1 и запиши в ADR. Кандидаты: `saveDocument` в PDF.js (Apache-2.0) и `IncrementalDocument` в Rust-крейте lopdf (MIT), оба умеют инкрементальное обновление. pdf-lib (MIT) пересобирает файл целиком и с 2021 года не выпускал релизов, бери его последним. Требования: лицензия из раздела 2, оригинальные страницы, закладки и формы не портятся.
- **Приёмка.** Копию открыть в браузере и в одной настольной программе для PDF. Выделения и заметки должны быть на тех же местах, что в читалке.
- **Запись в оригинал (опция, выключена по умолчанию).** Те же аннотации дописываются в сам файл. Перед первым включением покажи предупреждение: файл перезаливается целиком, а при правках с двух устройств облако может создать «конфликтную копию». Перед записью сохрани локальную резервную копию. После записи обнови `sha256` в `meta`, старое значение переложи в `previousSha256`.

### Markdown

Заметки группируются по главам из оглавления в порядке чтения. Закладки идут отдельным разделом. Если у заметки нет главы, используй «Без главы».

```markdown
---
title: Название
authors: [Автор]
bookId: uuid
sha256: hex
updated: 2026-10-26T12:00:00Z
---

# Название

## Глава 1

> Выделенный текст

Заметка читателя.

*18 %, 26 октября 2026*
```

### Чего не делаем

- Не меняем оригинальные EPUB и FB2.
- Не встраиваем заметки в EPUB. Позже можно рассмотреть копию EPUB с заметками в формате W3C EPUB Annotations, это пока рабочий черновик стандарта. Делай только по просьбе владельца.

## Скорость запуска, производительность и качество

Приложение должно быстро показывать текст последней книги. Цифру порога выбирают вместе с владельцем в конце фазы 0, по замерам на его устройствах, а не заранее.

### Замеры

- Измеряй холодный старт: от нажатия на значок до первой страницы последней книги. Замеры на Windows и на самом слабом Android-устройстве владельца делает он сам по твоей инструкции, а скрипт замера готовишь ты.
- Результаты записывай в `docs/PERF.md`: дата, устройство, версия приложения, число замеров, медиана.
- Ориентиры из сторонних замеров: Tauri на Windows стартует за сотни миллисекунд (311 мс в одном замере, 200–500 мс в другом). Для Android цифр запуска Tauri я не нашёл. Google считает холодный старт в 5 секунд и дольше чрезмерным. Это верхняя граница, целью надо ставить гораздо меньше.

### Правила быстрого старта

1. Показывай последнюю книгу сразу на сохранённой позиции, остальное делай в фоне.
2. Кэшируй в SQLite оглавление, обложки (миниатюры) и расчёт виртуальных страниц. Не считай их при каждом запуске.
3. Читай главы по мере надобности, не разбирай всю книгу сразу.
4. Начинай синхронизацию только после показа текста.
5. Индексируй библиотеку порциями и в фоне.
6. PDF рисуй постранично, страницы вне экрана не рисуй.
7. Тяжёлую работу выноси из основного потока: в задачи Rust и веб-воркеры.

### Качество и надёжность

- **Тесты.** Автоматические: слияние, локаторы, имена файлов, сборка Markdown, очередь синхронизации на `MemoryProvider`. Остальное проверяется ручными чек-листами из этого документа.
- **Данные не теряются.** Перед изменением схемы данных делай резервную копию локальной базы. Повреждённый JSON из облака не удаляй и не перезаписывай: сохрани копию и покажи ошибку.
- **Ошибки.** Понятные сообщения по-русски. Приложение не падает из-за недоступной сети или облака.
- **Анимации.** Если в WebView на слабом Android они рвутся, упрощай эффект или отключай по умолчанию, а не оставляй рывки. Запиши решение в `docs/PERF.md`.
- **Логи.** Без токенов, содержимого книг и личных данных.
- **Команды.** Запуск, тесты, линтер и сборку для Windows и Android опиши в README, чтобы владелец мог выполнить их сам.

## Правила работы Claude Code

1. Работай в git небольшими коммитами по смыслу, с понятными сообщениями. Сохрани копию этого документа в `docs/SPEC.md`. Если решения меняются, обнови копию и скажи владельцу.
2. Делай одну фазу за раз. В конце фазы обнови README, ADR, `docs/CHECKS.md` и `docs/PERF.md`.
3. Каждое существенное решение (библиотека, хранение токенов, формат) запиши коротким ADR: контекст, варианты, выбор, последствия.
4. Решения из раздела 2 не меняй. Если они мешают, остановись и опиши проблему владельцу.
5. Останавливайся и спрашивай владельца, когда: нужен ручной шаг из раздела 11, провалилась проверка № 1 или другая проверка из раздела 11 без запасного варианта, нужна зависимость с лицензией вне списка, требования конфликтуют, либо действие может удалить его данные.
6. Не трогай настоящие книги и облако владельца без явного указания. Тестируй на свободных книгах и на тестовой папке. Удаление чего-либо в облаке только с подтверждением.
7. Никаких токенов, ключей и идентификаторов клиентов в репозитории и логах. Локальную конфигурацию добавь в `.gitignore`, а рядом положи пример с пустыми значениями.
8. Код и ресурсы других читалок не копируй.
9. Не помечай функцию готовой, пока не выполнен её критерий приёмки из раздела 7. Если что-то не работает или не проверено, напиши об этом прямо в README или `docs/CHECKS.md`.
10. Держи код простым и без лишних абстракций. Исключение: интерфейс `SyncProvider` и слияние данных изолируй и покрой тестами.
11. Владелец лучше знает Python, чем TypeScript и Rust. В README коротко объясни структуру проекта, термины и как всё запускать. Нетривиальные места комментируй.
12. Скорость проверяй на реальном слабом Android-устройстве, а не только в эмуляторе.
13. Не публикуй приложение в магазинах, не регистрируй аккаунты и платные сервисы без просьбы владельца.

## Что делает владелец и открытые проверки

Некоторые шаги Claude Code не может выполнить сам. Подготовь для каждого пошаговую инструкцию и попроси владельца сделать его.

### Шаги владельца

1. Установить инструменты разработки по инструкции из README: Rust, Node.js, Android Studio с SDK и NDK, инструменты сборки для Windows.
2. Google Cloud: создать один проект, включить Drive API (и Google Picker API, если понадобится Picker), настроить экран согласия (внешний тип, статус «In production»), создать в этом же проекте клиенты OAuth: для Windows (Desktop app) и для Android (имя пакета и SHA-1, отдельно для отладочной и релизной подписи). Записать идентификатор и `client_secret` настольного клиента в локальную конфигурацию. Инструкцию пишешь ты в `docs/SETUP-GOOGLE.md`, включая команду для получения SHA-1.
3. Dropbox: создать приложение с типом доступа «App folder», разрешить public clients (PKCE), зарегистрировать redirect URI для Windows и Android и получить ключ приложения. Нужные права укажи в `docs/SETUP-DROPBOX.md`.
4. Подготовить слабое Android-устройство, компьютер с Windows, репозиторий на GitHub (может быть приватным) для проверок на Windows, а также отдельные тестовые аккаунты Google и Dropbox.
5. На условиях перехода между фазами принять решения: после фазы 0 — стек и порог времени запуска.

### Тестирование: кто что проверяет

Разработка идёт на macOS, поэтому программу для Windows Claude Code напрямую не запустит. Почти всё остальное он может проверять сам.

| Что проверяем | Чем | Кто |
| --- | --- | --- |
| Логика: слияние, локаторы, имена файлов, Markdown, очередь синхронизации | Юнит- и интеграционные тесты на `MemoryProvider`, запуск на Mac или в Linux-контейнере Docker | Claude Code |
| Интерфейс читалки на свободных тестовых книгах | Автоматические тесты в браузере без окна (инструмент выбери в ADR). Это не настоящий WebView Windows и Android, поэтому они проверяют логику интерфейса, а не его вид на устройстве | Claude Code |
| Android | Сборка APK, запуск в эмуляторе Android на Mac напрямую, а не в Docker, управление через adb, скриншоты, логи. Для входа в Google нужен образ эмулятора с Google Play | Claude Code |
| Приложение на macOS | Запуск собранного приложения и скриншоты. Автотестов WebDriver для macOS в Tauri нет, есть сторонний инструмент, я его не проверял | Claude Code |
| PDF-копия с аннотациями | Разбор аннотаций в файле и отрисовка страниц утилитами командной строки, сравнение с эталоном | Claude Code |
| Windows: сборка и автотесты | GitHub Actions на Windows. Tauri WebDriver поддерживает Windows. Условия и лимиты GitHub Actions я не проверял | Claude Code настраивает, владелец подключает репозиторий |
| Windows: запуск и замер скорости | Вручную по инструкции из README | Владелец |
| Реальный вход в Google и Dropbox | Один раз вручную на тестовом аккаунте. Токен сохраняется локально вне репозитория, дальше его используют автотесты | Владелец, затем Claude Code |
| Скорость и плавность анимаций на слабом Android | Замеры на реальном устройстве | Владелец |
| Озвучка, удобство чтения, внешний вид | Ручная проверка | Владелец |
| Переходы между фазами | Подтверждение | Владелец |

- Docker для Windows и Android не подходит. Docker Desktop на Mac запускает только Linux-контейнеры, а эмулятор Android в контейнере требует Linux с KVM. Docker используй только для тестов логики и моков.
- Сборка Windows-версии на Mac в Tauri экспериментальная. Основной путь — сборка в CI на Windows.
- Для реальных облаков используй только отдельные тестовые аккаунты, не основные.
- Виртуальную машину с Windows на Mac я не исследовал. Это возможный запасной вариант, если у владельца нет отдельного компьютера с Windows.
